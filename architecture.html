Behind the Scenes

How this website is built.
Simple, fast, and private.

Most websites rely on heavy frameworks, databases, and background trackers. This portfolio uses lightweight static files so it loads fast, has nothing to hack on a server, and respects your privacy.

Why Keep It Simple?

Fewer moving parts means fewer bugs and nothing exposed on a server.

No Database or Login Server

Websites with admin panels, databases, and server plugins need constant patching to stop SQL injection or account takeovers.

This portfolio is just static files hosted on GitHub Pages. There is no database, no login page, and no server code running in the background.

Static Files Only No Database GitHub Pages

No Visitor Tracking

Many sites load hidden analytics scripts or ad cookies that follow visitors around the web.

This site does not collect analytics, set tracking cookies, or send anything you type in the practice quiz or SanitizeAI tool to any outside server.

No Analytics No Tracking Cookies Local Browser Only

How Everything Fits Together

Three simple parts power the whole site without needing a backend.

One Clean List of Case Studies

Every case study follows the same clear layout (problem, steps, takeaways, and result) stored in projects.json so the Home page, Investigations hub, and individual pages stay in sync.

// Example entry inside projects.json

  "id": "unsloth-lora-secops",
  "category": "ai",

  "tags": ["Python", "AI", "Offline"]
}

Browser-Only Tools

The practice terminal, the interactive ISC2 CC quiz, and the SanitizeAI log cleaner all run directly in JavaScript inside your browser tab.

Nothing is uploaded anywhere, so you can even test private logs safely.

Shared Styles & Layout

Every page shares one stylesheet (assets/site.css) and one helper script (assets/site.js) for the menu, scroll animations, and footer.

Checks Before Publishing

Before pushing updates live to GitHub Pages, I run a few quick checks:

CHECK 1
Valid JSON & JavaScript
Make sure projects.json and every script parse cleanly with zero syntax errors.
CHECK 2
Working Links & Clean Copy
Verify all page links work and keep company experience vendor-neutral.
CHECK 3
Push to GitHub Pages
Push to the main branch and let GitHub Pages publish the updated static files automatically.

Quick Pre-Publish Check

What runs locally before pushing changes live.

# Check JSON, links, and JavaScript syntax
$ python verify_site.py
  [OK] projects.json is valid.
  [OK] All HTML pages checked with zero broken links.
  [OK] All JavaScript files passed syntax check.

# Deploy static site
$ git add . && git commit -m "Update site" && git push origin main
  [LIVE] GitHub Pages updated.
