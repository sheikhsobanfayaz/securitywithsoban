SIEM & Detection

Cloud Sandbox ATP & Endpoint EDR Telemetry Correlation

Bridging cloud sandbox malware detonation alerts at the perimeter with endpoint EDR process trees and host telemetry to determine true compromise impact.

Cloud SandboxATPEDRMalware DefenseIncident Response

Incident Scenario & Environmental Context

A perimeter Next-Gen Firewall cloud sandbox Advanced Threat Protection (ATP) service flagged a zero-day executable download as malicious. The alert required immediate investigation to determine whether the payload reached any enterprise workstation, whether execution occurred, and what containment actions were required.

Investigation Workflow

1. Retrieved the cloud sandbox behavioral detonation report: behavioral score, dropped files, registry modifications, process injection targets, and external C2 callback domains. 2. Extracted cryptographic file hashes (SHA-256 and MD5) and queried enterprise EDR telemetry across all endpoints. 3. Audited endpoint file event logs (DeviceFileEvents) to verify whether the binary was downloaded, saved to disk, or intercepted by local antivirus. 4. Inspected host process execution trees (DeviceProcessEvents) to confirm whether any user or script executed the payload. 5. Queried perimeter firewall egress logs for the external C2 callback IPs/domains identified in the sandbox report to determine if two-way communication occurred. 6. Formulated containment actions: automated EDR host isolation and enterprise-wide perimeter indicator blocking.

Technical Analysis & Telemetry Insights

Advanced Threat Protection (ATP) platforms utilize cloud-based sandbox environments to execute suspicious, previously unseen email attachments and web downloads in isolated virtual machines. While cloud sandbox analysis provides rich behavioral detonation telemetry (such as registry modifications, process injection, dropped payloads, and outbound C2 domains), a perimeter sandbox verdict alone does not answer the critical incident response question: Did the malicious payload execute on the target enterprise endpoint?

Correlating perimeter sandbox detections with host-level Endpoint Detection and Response (EDR) telemetry is essential to establish scope and impact: 1. Hash Propagation & EDR Search: Upon receiving a malicious sandbox verdict, the analyst immediately queries enterprise EDR telemetry across all workstations for the file's SHA-256 hash. 2. Process Tree & Lifecycle Analysis: If the file was written to disk, did the local antivirus/EDR agent quarantine it prior to execution, or did an end-user double-click the file? Inspecting parent-child process relationships (e.g. outlook.exe -> winword.exe -> powershell.exe) confirms execution attempts. 3. Behavioral Indicator Matching: The analyst cross-references the registry keys and mutex names identified during sandbox detonation against host forensic artifacts. 4. Perimeter Egress Validation: If host execution occurred, perimeter firewall traffic logs must be queried for the specific C2 callback IPs and domains identified in the sandbox report to confirm whether command-and-control communication was established or blocked.

Diagnostic Query / Logic Sample

DeviceFileEvents | where SHA256 == "3a1b8c2d9e0f..." or FileName endswith ".exe" | join kind=inner (DeviceProcessEvents | where InitiatingProcessFileName in ("outlook.exe", "msedge.exe")) on DeviceId | project TimeGenerated, DeviceName, ActionType, FileName, FolderPath, ProcessCommandLine

Competencies & Value Demonstrated

  • Integration of perimeter cloud sandbox detonation telemetry with endpoint EDR investigations
  • Layered threat validation connecting network gateway alerts to host-level process trees
  • Rapid querying of cryptographic hashes across multi-tenant endpoint fleets
  • Identification of malware execution lifecycle phases (delivery vs staging vs execution)
  • Evidence-driven containment planning balancing threat eradication with operational uptime

Incident Outcome & Verification Status

Verified Disposition

EDR telemetry verified the file was quarantined upon download by endpoint protection before execution occurred. No C2 callbacks were observed in firewall logs. Zero enterprise compromise confirmed.
