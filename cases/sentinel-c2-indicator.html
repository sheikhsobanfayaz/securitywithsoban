SIEM & Detection

Microsoft Sentinel Custom Network Indicator & Possible C2 Triage

Correlating endpoint process network events with perimeter firewall disposition to validate custom threat intelligence C2 indicator alerts.

Microsoft SentinelKQLEndpoint TelemetryC2 DetectionPalo Alto Logs

Incident Scenario & Environmental Context

A Microsoft Sentinel high-severity incident flagged a custom network indicator for potential command-and-control (C2) communication. Telemetry recorded an internal workstation (workstation-alpha, IP 10.16.56.241) executing an msedge.exe process that initiated communication to an external document utility domain, accompanied by specific SHA-256 and SHA-1 file hashes in the incident context.

Investigation Workflow

1. Scoped the Sentinel incident, extracting affected host, authenticated user, initiating process name, external destination domain, internal IPs, and file hashes. 2. Queried host-level endpoint network telemetry to evaluate whether the local operating system recorded a successful TCP connection or socket failure. 3. Queried perimeter firewall logs (CommonSecurityLog) for the source IP and timestamp window, inspecting the DeviceAction field (allow, deny, or drop) to determine actual perimeter disposition. 4. Audited SIEM events across all enterprise endpoints to establish if the custom indicator or external domain was observed on any other assets. 5. Validated file hashes against cloud sandbox detonation reports and threat intelligence reputation databases to assess payload malice. 6. Correlated timeline events to confirm whether subsequent lateral movement, persistence registry keys, or credential access occurred.

Technical Analysis & Telemetry Insights

A common pitfall in SOC alert triage is assuming that a high-severity alert or an endpoint connection event equals an active compromise. In modern enterprise environments, host-level telemetry (such as Sysmon Event ID 3 or EDR NetworkConnect) describes what the client operating system attempted or observed locally. If an endpoint reports 'ConnectionSuccess', that only indicates the local TCP socket handshake initiated; it does not account for perimeter security controls.

Conversely, perimeter firewalls (such as Palo Alto or enterprise NGFWs logging via CommonSecurityLog) track stateful inspection and enforcement. An event with DeviceAction equal to 'deny' or 'drop' proves the traffic was blocked before leaving the perimeter, rendering an automated C2 callback harmless. Furthermore, indicators pointing to dual-use utility domains (such as online PDF conversion or file-sharing tools) frequently trigger custom threat intelligence rules when users interact with unapproved web utilities.

Rather than isolating the asset immediately based solely on an indicator match, the analyst must verify the exact URI, analyze DNS resolution history, inspect parent-child process relationships (e.g. browser vs unauthorized executable), evaluate payload hashes against cloud sandbox detonations, and determine if identical indicators appear across other enterprise nodes before making a defensible containment decision.

Diagnostic Query / Logic Sample

CommonSecurityLog | where TimeGenerated >= ago(24h) | where SourceIP == "10.16.56.241" or DestinationIP == "10.16.56.241" | project TimeGenerated, DeviceAction, SourceIP, DestinationIP, DestinationPort, Activity

Competencies & Value Demonstrated

  • Correlation of SIEM alert context with endpoint and network evidence
  • Clear analytical distinction between an alert trigger and confirmed compromise
  • Deep log-interpretation understanding of endpoint socket events versus perimeter firewall DeviceAction disposition
  • Structured multi-source scoping across internal endpoints to confirm incident blast radius
  • Defensible, evidence-driven escalation and incident documentation under strict SLAs

Incident Outcome & Verification Status

Verified Disposition

Investigation established that perimeter firewall controls blocked the outbound connection attempt (DeviceAction: drop). Compromise was not established from the evidence reviewed. The host remained operational under ongoing monitoring.
